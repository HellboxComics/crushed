# FULL AUDIT OF THE WORKFLOW - 2026-10-04 (Cody: "fine tooth comb level audit and optimization ... full redesigns")

Three independent readers went through every stage against one standard:
is each answer MEASURED or guessed; is a wrong answer CAUGHT by a check that gates the build; does every
cache/keep INVALIDATE when any of its inputs change; is anything ITEM-SPECIFIC; where does the TIME go; can the
ENGINEER (Cody's local coding brain) succeed on its own. ~180 findings. The full lists are in the three reports
below this summary. What follows is the ROOT CAUSES and the REDESIGN, in the order it is being built.

## Root causes (each one explains dozens of findings)

RC1  THE STEP CHECKS GATE NOTHING. Every review-sheet check (label score, colors, overlaps, parts plan, board parts,
     box sides, kit) only goes into review.json for the engineer to read; the verdict is built from check_model
     alone. A label scoring 2/10, a board with 0 parts, a part Blender could not build - all go on to the judge and
     can pass. => every sheet check with ok False is a failure of the build ("step: <check>").
RC2  FAILURES ARE CACHED AS ANSWERS, AND KEYS MISS INPUTS. vet "match 0" on a timeout, quick look "none", panel {},
     captcha searches with n=0, a partial word read, an empty label-parts hunt - all stored and never retried. Keys
     miss the brain model, the prompt text, the code of the step, the photos, the kit. Hand-bumped VERSION numbers
     are forgotten. => one keep discipline (kept.py): key = bytes of inputs + brain + HASH of the prompt text + hash
     of the step's code; never store a failed/empty answer; Redo clears the item's keeps.
RC3  "NOTHING INVENTED" IS NOT ENFORCED. Fixed logo crops pasted on unseen sides; brand panels and 2.2 mm type
     invented on sides no photo shows; random solder traces; a steel bracket on every board; sprinkles and a pastry
     hard-coded into the carton builder; "slight wear" asked for; only_words passes fragments. => an unseen side is
     the measured base color plus facts WITH receipts, flagged; every side OCR'd and any token not traceable to a
     confirmed word or a receipted fact fails; every invented detail removed.
RC4  THE PASS IS THE BRAIN'S WORD, AND THE ENGINEER'S OWN CODE CAN OUTVOTE THE INDEPENDENT CHECK. judge trusts
     v["pass"] and ignores its own inventory counts; majority-of-three lets F1+F2 (the engineer's code) beat Fp;
     kept.py (the verdict cache) is unlocked and shared with test builds; run_fingerprint misses check_model,
     version_marks, route_of_card. => pass computed in code from the fields; Fp is a veto; kept.py, cards.py
     locked; test builds get their own kept store; frozen defs extended.
RC5  SIZE IS NEVER MEASURED. A missing catalog size becomes a 0.1 m cube that then "passes" measure_size against
     itself; kit sizes from the web are kept without the numbers appearing in the snippet; the pick's shape is
     "used anyway" when it disagrees 20%+. => no size, no build; kit sizes only with the numbers in the source;
     the pick's proportions (mask) must agree with the size or the build stops with "catalog size disagrees".
RC6  THE PICK AND THE IDENTITY ARE NEVER VERIFIED. The pick is "exact by definition"; auto-pick with one candidate;
     the "seen" marks are an unverifiable count; era names from memory sink right photos. => the careful look
     records its own match for the pick and a disagreement is a sheet failure; auto-pick needs 2+ candidates and
     named marks; era names kept only with web evidence.
RC7  THE ENGINEER CANNOT SUCCEED AS SET UP. The engineer is OFF unless settings.json says engineer:true; it cannot
     test one step (only a full production rebuild incl. every export); the time reserve allows ~1 test build;
     a proven fix is lost when time runs out after a later edit; `clear` is not in the code key so a right rebuild
     is answered from a wrong cache; neighbours count "not_judged" as a new failure; it cannot read the dossier or
     card; STEP_FILES points it at locked files; portal replies repeat (done.json skipped on continue). => each
     fixed as part of the loop redesign below.
RC8  THE DELIVERABLE IS NOT ONE STANDARD. Box/flat: no physics, no material checks (names end in _print); UVs
     overlap on assembly boxes and pcb parts; inside parts have no UVs; textures named six ways; .mtl/.ma lose the
     tiling scale; deliver.verify never re-imports. => one export contract per part: unique UVs, base/mr/normal maps
     named <asset>_<part>_<map>, physics on every route, verify by re-import.
RC9  ITEM-SPECIFIC CODE. Pop-Tarts contents in the carton builder; battery words in prompts and typicals
     ("PowerCheck strip" in the kit); "+" marks; pcb bracket; Pop-Tarts examples in ID_Q/QUICK_Q; carton flaps on
     every card box. => removed or moved into kits the AI writes.
RC10 THE HUNT FAILS SILENTLY. A captcha returns 0 photos, the search is recorded as done and the dossier marked
     done. => a captcha raises; searches record their outcome; "done" only when the hunt really ran.

## The redesign, in build order (each stage whole, tested, then pushed - never a piece)

S1  GATES: review failures fail the build; judge pass computed in code; Fp veto; frozen defs; kept.py/cards.py
    locked; test builds get an isolated kept store; check_version = hash of the check code and prompts.
S2  KEEP DISCIPLINE: kept.step() with full keys and no stored failures, applied to vet, quick/careful looks,
    panels, words, label parts, parts plan, board parts, same_design, look_faces/unrolled, era version, cards,
    classification; Redo clears an item's keeps; label_kept key complete.
S3  ENGINEER LOOP: settings default ON; a `test_step` tool that runs one step (layout, labelart, parts.clean, a
    builder on a spec) in seconds; the dossier/card readable; STEP_FILES only unlocked files; reserve from real
    trial lengths with the confirm = re-judge only (no second full build when the model's pictures match);
    proven code restored at the end; `clear` in the code key; neighbours via _fails_of; attempts refunded on
    machine failures; portal done.json saved per message; budget shown each turn.
S4  SIZE AND PICK VERIFIED: no default size; pick proportions vs catalog size; kit sizes with numbers in source;
    pick's own match recorded; auto-pick rules; era names with evidence.
S5  NOTHING INVENTED: unseen sides plain + receipted facts; fallback logo/picture crops removed; solder side,
    bracket, carton contents, sprinkles, wear removed or made measured/kit-driven; only_words token-exact; every
    side OCR'd for untraceable text.
S6  DELIVERABLE CONTRACT: per-part unique UVs and maps on every route; physics everywhere; names; verify by
    re-import; box route material checks.
S7  ITEM-SPECIFIC REMOVAL and prompt neutralization (examples, typicals, marks).
S8  HUNT: captcha raises; outcomes recorded; dossier done only when complete; shared looks keyed once.
S9  EFFICIENCY: real builds fail fast too; renders once; judge calls batched; brain reloads avoided (one num_ctx);
    trials without exports; disk cleanup.

Status is kept at the bottom of this file as each stage lands.
